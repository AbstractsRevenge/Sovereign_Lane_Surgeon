# Bundle Distribution

The device trees are data. The binary always embeds the **manifests** that describe them; the
**content** can come from anywhere, and is verified before use.

## Why this exists

Embedding about 712 MB of device trees makes the binary self-contained, which is the right default
for a workstation: `go build` and run, with no external checkout and no `repo sync`. It is the
wrong shape for continuous integration or for distribution.

## The four manifests

`go:embed` carries regular-file content and nothing else. Everything else it loses travels beside
it, generated by one command from one walk:

| Manifest | Carries | Why |
|---|---|---|
| `.sha256` | content hash, size, path | identity and verification |
| `.exec` | executable bits | the build runs some of these scripts; without the bit, "permission denied" |
| `.symlinks` | link paths and targets | AOSP uses symlinks as compatibility headers |
| `.dirs` | directories holding no files | none exist today; the manifest exists so a future one cannot vanish silently |

Each of the first two was discovered by a build failing far from the cause. The pattern was fixed
by making one generator emit all of them, so a new kind of loss cannot be left without something
regenerating it, and by adding `bundle audit` to prove the set complete against a real source tree.

## Building without the content

```bash
go build -tags nobundle -o sovereign-lane-surgeon .   # about 15 MB
```

Supply the content at run time, in this order of preference:

```bash
create -stock -bundle-dir /path/to/bundle     # or $SLS_BUNDLE_DIR
create -stock -bundle-url https://…/bundle.tar.gz   # or $SLS_BUNDLE_URL, cached after first fetch
```

Every non-embedded source is verified file by file against the embedded manifests before use, and
an archive that does not match the manifests this binary was built with is refused and removed.

## Publishing an archive

```bash
./sovereign-lane-surgeon bundle export -out /path/to/publish
```

Writes the archive and its manifest, named by bundle id. A slim binary of the same revision then
fetches and verifies it. The v0.4.0 release carries exactly this pair, so the slim binary from that
release runs with:

```bash
-bundle-url https://github.com/AbstractsRevenge/Sovereign_Lane_Surgeon/releases/download/v0.4.0/sls-bundle-692dded8e614a01b.tar.gz
```

fetched once into the cache and verified file by file against the manifest compiled into the
binary; an archive that does not match is refused.

## Inspecting

```bash
./sovereign-lane-surgeon bundle info                 # id, counts, where the content came from
./sovereign-lane-surgeon bundle verify               # content matches the manifests
./sovereign-lane-surgeon bundle audit -source <tree> # the bundle matches the AOSP tree it was cut from
```
